# M1 骨架 — 具体实现方案

> 目标：`spark "你好"` 能流式回复  
> 范围：事件日志 + Context + 事件总线 + LLM 适配器（流式）+ BlockAssembler + Agent 循环 + CLI  
> 工具：M1 不含工具注册表，LLM 请求不带 tools 参数  
> 测试：M1 不写单元测试，M2 补  
> 预估：Day 1-2

### Step 1: `src/core/error.ts` — 结构化错误

**职责**：定义 LlmError 和工具错误转换函数。

**接口**：

```typescript
// LLM 失败的结构化描述
export interface LlmFailure {
  message: string
  code: string       // 'AUTH' | 'RATE_LIMIT' | 'NO_ADAPTER' | 'UNKNOWN'
  status?: number    // HTTP 状态码
}

// LLM 层抛出的错误
export class LlmError extends Error {
  readonly failure: LlmFailure
```

**实现要点**：
- `LlmError` 继承 `Error`，额外携带 `failure` 结构化对象

- 此文件在 M1 中 `toolErrorResult` 暂时留空实现（M2 工具系统才用到）

### Step 2: `src/core/events.ts` — 事件总线

**职责**：类型化事件分发（emit 广播）和 waterfall 中间件链。

**接口**：

```typescript
// 监听器函数类型
type Listener<T = unknown> = (data: T) => void | Promise<void>

// waterfall 处理器：接收当前值 + next 函数，返回变换后的值
type WaterfallHandler<T> = (value: T, next: (v: T) => Promise<T>) => Promise<T>

export class EventBus {
  // 注册事件监听器，返回 disposer
  on<T>(event: string, listener: Listener<T>): () => void

  // 广播事件（通知所有监听器，不等待返回值）
  emit<T>(event: string, data: T): void

  // 注册 waterfall 处理器，返回 disposer
  waterfall<T>(event: string, handler: WaterfallHandler<T>): () => void

  // 执行 waterfall 链：初始值依次经过所有处理器变换
  runWaterfall<T>(event: string, initial: T): Promise<T>
}
```

**实现要点**：
- 内部用 `Map<string, Set<Listener>>` 管理 emit 监听器
- 内部用 `Map<string, WaterfallHandler[]>` 管理 waterfall 处理器（有序数组）
- `emit` 对每个 listener 调用 `Promise.resolve(listener(data)).catch(console.error)`——listener 异常不阻塞其他 listener
- `runWaterfall` 用递归+闭包实现链式调用：`handlers[0](value, v1 => handlers[1](v1, v2 => ...))`
- 所有 `on` 和 `waterfall` 返回 disposer 函数 `() => void`，用于取消订阅
- 事件名用字符串（如 `'prompt/assemble'`、`'llm/stream'`），不做枚举以保持灵活性

### Step 3: `src/core/context.ts` — 服务仓库

**职责**：依赖注入容器，持有所有共享服务的引用。

```typescript
export class Context {
```

**实现要点**：

- 后续 M2 加入 `ToolRegistry`，M4 加入 `CompactionService`

### Step 4: `src/core/session.ts` — 事件日志

**职责**：append-only 事件日志、消息投影（deriveMessages）、重放。

**接口**：

```typescript
// 会话事件（判别联合）
export type SessionEvent =
  | { seq: number; time: number; type: 'turn/start'; data: { turn: number } }
  | { seq: number; time: number; type: 'turn/end';   data: { turn: number; reason: TurnEndReason } }
  | { seq: number; time: number; type: 'step/start'; data: { turn: number; step: number } }
  | { seq: number; time: number; type: 'step/end';   data: { turn: number; step: number } }
  | { seq: number; time: number; type: 'user/message';      data: UserMessage }
  | { seq: number; time: number; type: 'assistant/chunk';   data: { turn: number; step: number; chunk: StreamChunk } }
  | { seq: number; time: number; type: 'assistant/message'; data: { turn: number; step: number; message: AssistantMessage; usage?: TokenUsage } }
  | { seq: number; time: number; type: 'tool/call';   data: ... }
  | { seq: number; time: number; type: 'tool/result'; data: ... }
  | { seq: number; time: number; type: 'request/header'; data: ... }

export type TurnEndReason =
  | { kind: 'completed' }
  | { kind: 'max-tokens' }
  | { kind: 'error'; error: LlmFailure }
  | { kind: 'aborted'; reason: string }

export class Session {
  readonly id: string

  // 追加事件，返回带 seq 的完整事件
  append<T extends SessionEvent['type']>(
    type: T,
    data: Extract<SessionEvent, { type: T }>['data'],
    options?: { surfaceOp?: 'append' | { op: 'replace'; start: number; end: number } }
  ): SessionEvent

  // 从日志投影模型可见的消息历史
  deriveMessages(): DerivedMessage[]

  // 获取原始日志
  getLog(): readonly SessionEvent[]

  // 重放事件序列（用于恢复）
  replay(events: SessionEvent[]): void
}
```

**实现要点**：

1. **append**：
   - 内部维护 `seq` 计数器（从 0 单调递增）
   - 每次 append：`seq++`、`time = Date.now()`、构造事件对象、推入日志数组
   - `surfaceOp: 'append'` 标记的事件（user/message、assistant/message、tool/result）进入投影
   - `surfaceOp: { op: 'replace', start, end }` 用于 M4 压缩，M1 暂不实现

2. **deriveMessages**（核心自研逻辑）：
   - 遍历日志，只投影 Surface 事件：
     - `user/message` → 直接推入
     - `assistant/message` → 检查 `content.length > 0`（空内容跳过，仅含 usage 的事件）
     - `tool/result` → 直接推入（M1 无工具调用，此分支暂不会触发）
   - 维护游标 `derivedCursor`：新事件增量追加，避免每次全量扫描
   - M4 compaction 时通过 `replace` 标记重置游标

3. **replay**：
   - 清空当前日志，重置 seq
   - 按顺序调用 append（跳过 surfaceOp 判断，全部追加）
   - 用于 M5 持久化恢复

4. **事件数据类型**（M1 用到的子集）：
   ```typescript
   export interface UserMessage {
     id: string
     role: 'user'
     content: string            // M1 简化为纯文本（M2 支持 ContentBlock[]）
     source: 'human' | 'injected'
   }

   export interface AssistantMessage {
     id: string
     role: 'assistant'
     content: ContentBlock[]
   }

   export type ContentBlock =
     | { type: 'text'; text: string }
     | { type: 'tool-call'; id: string; name: string; arguments: string }
     | { type: 'tool-result'; callId: string; content: string; isError: boolean }

   export interface TokenUsage {
     promptTokens: number
     completionTokens: number
     totalTokens: number
   }
   ```

### Step 6: `src/core/llm.ts` — LLM 适配器 + 流式解析

**职责**：OpenAI 兼容 API 的流式调用、SSE 增量解析、BlockAssembler 组装完整消息。

这是 M1 最核心的自研模块，包含三个关键组件：

#### 6.1 消息类型

```typescript
// 流式 chunk（SSE 增量分类）
export type StreamChunk =
  | { kind: 'content'; text: string }
  | { kind: 'tool-call-part'; index: number; id?: string; name?: string; argsFragment: string }
  | { kind: 'finish'; reason: string | null }

// LLM 请求选项
export interface GenerateOptions {
  model: string
  messages: ApiMessage[]
  tools?: ToolSchema[]       // M1 不传
  provider?: string
}

// API 消息格式（OpenAI 兼容）
export type ApiMessage =
  | { role: 'system'; content: string }
  | { role: 'user'; content: string }
  | { role: 'assistant'; content: string | null; tool_calls?: ApiToolCall[] }
  | { role: 'tool'; tool_call_id: string; content: string }
```

#### 6.2 streamModel — 流式请求（自研）

```typescript
export async function* streamModel(
  client: OpenAI,
  request: GenerateOptions,
  signal: AbortSignal,
): AsyncIterable<StreamChunk>
```

**实现要点**：
- 调用 `client.chat.completions.create({ ..., stream: true }, { signal })`
- 遍历 `for await (const part of stream)`：
  - `delta.content` → `yield { kind: 'content', text }`
  - `delta.tool_calls` → 遍历每个 tc，`yield { kind: 'tool-call-part', index, id, name, argsFragment }`
  - `finish_reason` → `yield { kind: 'finish', reason }`
- AbortSignal 取消：传给 `create` 的第二个参数 `{ signal }`，OpenAI SDK 会中断连接

#### 6.3 BlockAssembler — 增量组装（自研核心）

```typescript
export class BlockAssembler {
  private contentParts: string[] = []
  private toolParts = new Map<number, { id?: string; name?: string; args: string }>()
  private finishReason: string | null = null

  // 喂入一个 chunk
  feed(chunk: StreamChunk): void

  // 完成组装，返回 ContentBlock 数组
  finish(): { content: ContentBlock[]; finishReason: string | null }

  // 解析 tool-call（含 JSON 容错）
  parseToolCalls(): ParsedToolCall[]
}
```

**实现要点**：

1. **feed(chunk)**：
   - `chunk.kind === 'content'` → `this.contentParts.push(chunk.text)`
   - `chunk.kind === 'tool-call-part'` → 按 `chunk.index` 从 `toolParts` Map 取出或创建条目，拼接 `argsFragment` 字符串
   - `chunk.kind === 'finish'` → `this.finishReason = chunk.reason`

2. **finish()**：
   - 合并 contentParts → `{ type: 'text', text: joined }`
   - 遍历 toolParts（按 index 排序）→ `{ type: 'tool-call', id, name, arguments }`
   - 返回 `{ content: blocks, finishReason }`

3. **parseToolCalls()**（关键容错逻辑）：
   - 从 finish() 结果过滤 tool-call 块
   - 对每个 tool-call 的 arguments 做 `JSON.parse`：
     - 成功 → `{ id, name, args: parsed }`
     - 失败 → `{ id, name, args: { _raw: arguments } }`（保留原文，不崩溃）
   - 这是模型输出解析的核心难点：arguments 是分片 JSON，必须聚合后整体 parse

#### 6.4 toApiMessages — 历史转换

```typescript
export function toApiMessages(history: DerivedMessage[]): ApiMessage[]
```

**实现要点**：
- `role: 'user'` → `{ role: 'user', content: typeof msg.content === 'string' ? msg.content : ... }`
- `role: 'assistant'` → 提取 text 块拼为 content，提取 tool-call 块转为 `tool_calls` 数组
- `role: 'tool'` → `{ role: 'tool', tool_call_id: msg.callId, content: msg.content }`
- M1 阶段 assistant 消息只有 text 块（无工具调用），简化实现

#### 6.5 LlmAdapter 类

```typescript
export class LlmAdapter {
  private client: OpenAI

  constructor(config: { apiKey: string; baseURL?: string })

  // 流式请求（带重试）
  async stream(request: GenerateOptions, signal: AbortSignal): Promise<{
    message: AssistantMessage
    usage?: TokenUsage
  }>
}
```

**实现要点**：
- 构造函数创建 `new OpenAI({ apiKey, baseURL })`
- `stream` 方法内部：
  1. 创建 `BlockAssembler`
  2. 调用 `streamModel(client, request, signal)`
  3. 遍历 chunk，逐个 `assembler.feed(chunk)`
  4. 同时通过 `ctx.emit('assistant/chunk', chunk)` 实时广播（CLI 流式打印用）
  5. 流结束后 `assembler.finish()` 得到完整消息
  6. 返回 `{ message: { id: uid(), role: 'assistant', content }, usage }`

**重试策略**（M1 简化版）：
- 429 → 指数退避重试（1s, 2s, 4s），最多 3 次
- 401 → 不重试，抛 `LlmError('AUTH', 'AUTH')`
- 网络超时 → 重试 1 次
- M1 重试逻辑直接写在 `stream` 方法内，M2 提取到 waterfall 中间件

### Step 10: `src/core/loop.ts` — Agent 循环

**职责**：turn/step 状态机，驱动 LLM 请求和工具执行。M1 无工具执行，循环简化。

**接口**：

```typescript
export interface Agent {
  readonly session: Session
  readonly inbox: Inbox
  readonly ctx: Context
  readonly cwd: string

  followup(content: string): void    // 用户输入 → 新 turn
  steer(content: string): void       // 追加输入 → 当前 step（M2 用）
  cancel(reason: string): void       // 取消
}

export class SparkAgent implements Agent {
  constructor(ctx: Context, config: SparkConfig)

  followup(content: string): void
  cancel(reason: string): void
}
```

**实现要点**：

1. **状态管理**：
   - `phase: 'idle' | 'running'`（M1 无 maintenance）
   - `turn: number`、`step: number` 计数器
   - `abort: AbortController | null`（取消控制）

2. **followup(content)**：
   - 构造 `UserMessage { id: uid(), role: 'user', content, source: 'human' }`
   - `inbox.append('next-turn', msg)`
   - `wakeDriver()`

3. **wakeDriver()**：
   - 如果 `phase !== 'idle'`，直接返回（不重入）
   - `phase = 'running'`
   - `while (await this.runTurn()) {}`（循环处理所有 pending 输入）
   - `phase = 'idle'`

4. **runTurn()**（M1 简化版）：
   ```
   turn++
   session.append('turn/start', { turn })

   // (A) 认领输入
   const messages = inbox.claim('next-turn', turn)
   if (messages.length === 0) break

   // (B) 组装 prompt
   const assembly = assemblePrompt(session, config)
   session.append('step/start', { turn, step: 0 })
   for (const m of messages) session.append('user/message', m)

   // (C) 构建历史 + 调 LLM
   const history = session.deriveMessages()
   const apiMessages = [
     { role: 'system', content: assembly.header.systemPrompt },
     ...toApiMessages(history)
   ]
   const request = { model: assembly.header.model, messages: apiMessages }

   const result = await llmAdapter.stream(request, abort.signal)

   // (D) 记录结果
   session.append('assistant/message', { turn, step: 0, message: result.message, usage: result.usage })
   session.append('step/end', { turn, step: 0 })
   session.append('turn/end', { turn, reason: { kind: 'completed' } })

   return inbox.hasPending()  // 是否还有待处理输入
   ```

5. **错误处理**：
   - LLM 错误 → `session.append('turn/end', { reason: { kind: 'error', error: e.failure } })`
   - 未知异常 → 同上，code 设为 'UNKNOWN'
   - 错误后抛出给上层 UI 处理

6. **cancel()**：
   - `abort?.abort('user-cancelled')`
   - LLM 流式请求会中断（AbortSignal）
   - 记录 `turn/end reason: { kind: 'aborted' }`

### Step 11: `src/index.ts` — CLI 入口 + REPL

**职责**：命令行参数解析、初始化、交互式 REPL。

**实现要点**：

```typescript
#!/usr/bin/env node

// 1. 解析配置
const config = loadConfig(process.argv)

// 2. 创建核心服务
const ctx = new Context()
const llm = new LlmAdapter({
  apiKey: process.env[config.provider.apiKeyEnv]!,
  baseURL: config.provider.baseURL,
})
ctx.provide('llm', llm)
ctx.provide('config', config)

// 3. 创建 Agent
const agent = new SparkAgent(ctx, config)

// 4. CLI 模式分支
if (config.oneShotTask) {
  // one-shot 模式：执行任务 → 打印结果 → 退出
  agent.followup(config.oneShotTask)
  // 等待 turn 结束，打印最终 assistant 消息
} else {
  // 交互式 REPL
  const rl = createInterface({ input: process.stdin, output: process.stdout })

  // 订阅事件流做实时渲染
  ctx.events.on('assistant/chunk', (data) => {
    process.stdout.write(data.chunk.text)  // 流式打印
  })
  ctx.events.on('tool/call', (data) => {
    console.log(`\n🔧 ${data.name}(${data.arguments})`)
  })
  ctx.events.on('tool/result', (data) => {
    // M1 无工具，此分支暂不触发
  })

  // 输入循环
  while (true) {
    const input = await rl.question('\n> ')
    if (!input.trim()) continue
    if (input.trim() === '/exit') break

    agent.followup(input)

    // 等待当前 turn 完成（通过事件或 Promise）
    await waitForTurnEnd(agent)
  }

  rl.close()
}
```

**事件渲染**（纯函数，与 Web 共用逻辑）：
- `assistant/chunk` → `process.stdout.write(chunk.text)`（逐字流式打印）
- `tool/call` → `🔧 name(args)` 形式（M1 不触发）
- `tool/result` → 绿色/红色缩进块（M1 不触发）
- `turn/end` → 回到输入等待

**Ctrl+C 处理**：
- 第一次 → `agent.cancel('user-interrupt')`，中断当前回合
- 第二次 → `process.exit(0)`，退出进程

## 5. 关键设计决策（答辩准备）

M1 阶段涉及的设计决策，面试时可能被问到：

### Q: 为什么用 EventBus 而不是直接函数调用？

**A**：EventBus 的 `waterfall` 模式让 prompt 组装、压缩策略等横切逻辑与核心循环解耦。M1 虽然只有一个简单的 prompt，但 M2 加工具 schema、M4 加压缩时，只需注册 waterfall handler，不修改 loop.ts。这借鉴了 DSH 的"类型化事件注入策略"。

### Q: BlockAssembler 为什么按 index 聚合 tool-call？

**A**：OpenAI 流式 API 的 tool-call arguments 是按 index 分片发送的 JSON 字符串增量（如 `{"command":` → `"ls"}` → `}`）。必须按 index 聚合后整体 JSON.parse。且 parse 可能失败（模型输出非法 JSON），所以要做容错——保留原文交给工具层。这是 M1 最关键的自研解析逻辑。

### Q: Session 的 deriveMessages 为什么维护游标？

**A**：每次 LLM 请求都需要完整历史。如果每次都全量扫描日志，O(n) 复杂度在长对话中会变慢。维护游标做增量投影，新事件只需追加，compaction 时重置。保证了"模型可见 ⟺ 已记录"的不变式。

### Q: 为什么 M1 不做工具？

**A**：M1 的目标是打通主干——从用户输入到 LLM 流式响应的完整链路。工具是独立模块，M2 引入 ToolRegistry 后只需在 loop.ts 的 runTurn 中加一步"提取 tool-call → 执行"，不影响已有架构。增量开发，每步可验证。
