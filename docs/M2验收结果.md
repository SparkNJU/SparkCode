## 4. 实现偏差分析

### 4.1 偏差 1：ToolRegistry 简化了 pre/postExecute 钩子

**现状**：技术方案 §4.1 设计了 `preExecute` 和 `postExecute` waterfall 钩子（用于权限/沙箱/审批），M2 实现中未包含。

**原因**：M2 阶段无权限审批需求，钩子机制增加复杂度但无实际用途。

**影响**：无功能影响。后续如需实现权限审批（如写守卫），可在 ToolRegistry 中补充钩子。

### 4.2 偏差 2：bash 工具超时双重控制

**现状**：技术方案仅使用 `spawn` 的 timeout 参数，M2 实现同时使用了 `setTimeout` 手动 kill。

**原因**：Node.js `spawn` 的 `timeout` 参数行为在不同平台不一致（Windows 上可能不生效），手动 timer 更可靠。

**影响**：正面偏差，提升了跨平台可靠性。

### 4.3 偏差 3：tool/call 和 tool/result 渲染未区分成功/失败颜色

**现状**：M1 预留的事件渲染监听器已实现，但成功/失败的颜色区分可能需要根据实际 `isError` 字段判断。

**原因**：M1 的渲染代码已经处理了 isError 字段，M2 无需额外修改。

**影响**：无功能影响。

## 5. 验收结论

### 通过项

- ✅ ToolRegistry 注册表 + 统一执行管道（超时 + 错误规范化）
- ✅ bash 工具：跨平台 shell 执行（Windows cmd / Unix bash）
- ✅ bash 工具：AbortSignal 取消支持
- ✅ bash 工具：输出截断（20,000 字符上限，头 80% + 尾 20%）
- ✅ Agent 循环 multi-step 重构（while 循环 + tool-call 检测 + 执行）
- ✅ executeToolCalls 串行执行 + JSON 解析容错
- ✅ prompt waterfall 模式 + 工具 schema 动态注入
- ✅ usage 提取（stream_options + TokenUsage）
- ✅ `!` 前缀命令模式（直接执行 Shell，跳过 LLM）
- ✅ 欢迎消息包含命令模式提示
- ✅ M1 全部 4 项偏差已修复或确认无需修复
- ✅ TypeScript strict 模式编译通过

### 未通过 / 待改进

- ⚠️ pre/postExecute 钩子未实现（M2 合理简化，后续按需补充）
- ⚠️ 后台任务（run_in_background + job_* 工具族）未实现（计划 M6）

### 总评

M2 工具系统**通过**验收。核心链路（用户输入 → LLM 决策 → 工具执行 → 结果反馈 → 循环继续）完整打通。ToolRegistry 提供了可扩展的工具注册框架，bash 工具实现了跨平台 shell 执行。Agent 循环从 M1 的单步执行升级为 multi-step 循环，支持模型自主决定调用工具。`!` 命令模式提供了快速 shell 访问，不消耗 token。M1 的 4 项偏差全部修复。
