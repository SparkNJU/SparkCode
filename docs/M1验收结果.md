## 3. 实现偏差分析

### 3.1 偏差 1：Agent 循环无 multi-step

**现状**：`runTurn()` 只执行一个 step（单次 LLM 请求 → 记录结果 → 结束），不处理 tool-call 后的循环。

**原因**：M1 不含工具系统，模型不会返回 tool-call，因此 multi-step 循环不会触发。

**影响**：无功能影响。M2 引入工具后需要重构 `runTurn()` 为 while 循环。

**修复计划**：M2 Step 6 重构 runTurn，加入 tool-call 检测 → 执行 → 循环逻辑。

### 3.2 偏差 2：usage 未提取

**现状**：`LlmAdapter.streamWithRetry()` 收到 API 响应后，`usage` 变量始终为 `undefined`。

**原因**：OpenAI 流式 API 的 usage 在最后一个 chunk 的 `x_usage` 字段（需设置 `stream_options: { include_usage: true }`），当前代码未启用。

**影响**：`assistant/message` 事件中无 usage 数据。M4 上下文管理需要 token 计量。

**修复计划**：M2 启用 `stream_options: { include_usage: true }`，从流中提取 usage。

### 3.3 偏差 3：prompt/assemble 未走 waterfall

**现状**：`loop.ts` 直接调用 `assemblePrompt(session, config)`，未通过 `ctx.waterfall('prompt/assemble', ...)` 中间件链。

**原因**：M1 只有固定的系统提示词，不需要中间件扩展。

**影响**：M2 添加工具 schema 注入时，需要同时将 prompt 组装改为 waterfall 调用。

**修复计划**：M2 Step 7 改为 waterfall 模式，工具 schema 通过中间件注入。

### 3.4 偏差 4：isProjected() 永远返回 false

**现状**：`Session.isProjected()` 硬编码返回 `false`。

**原因**：增量投影由 `derivedCursor` 控制，`isProjected` 未实际使用。

**影响**：无功能影响。deriveMessages() 行为正确。

**修复计划**：可保持现状（cursor 已足够），或 M4 重构时清理。

## 4. 已发现的潜在问题

### 4.1 step/start 和 step/end 事件时序

**问题**：当前 `runTurn()` 在 LLM 调用前 append `step/start`，LLM 调用后 append `step/end`。当 M2 引入 multi-step 时，`step/end` 应在 tool 执行完毕后追加，而非 LLM 响应后。

**影响**：M2 需要调整 step 事件的时序。

### 4.2 tool/call 事件未发射

**问题**：`loop.ts` 中没有 `session.append('tool/call', ...)` 的逻辑（因为 M1 无工具）。

**影响**：M2 实现工具执行时需补充 tool/call 事件发射。

### 4.3 one-shot 模式的 chunk 收集

**问题**：`runOneShot()` 通过事件监听收集文本，但如果 LLM 出错，`finalText` 可能不完整。

**影响**：边界情况，不影响核心功能。

### 通过项

- ✅ 事件日志（Session）完整实现 12 种事件类型

- ✅ EventBus emit + waterfall 双模式
- ✅ Context 服务仓库 + 快捷方法
- ✅ LLM 适配器流式调用 + BlockAssembler 增量组装
- ✅ SSE 增量解析（content / tool-call-part / finish 三类）
- ✅ tool-call arguments 分片 JSON 聚合 + 容错
- ✅ 错误处理：401 不重试、429 指数退避、网络超时重试
- ✅ CLI REPL 交互 + one-shot 模式
- ✅ 事件渲染（流式文本、工具卡片预留、错误着色）
- ✅ Ctrl+C 取消 + /exit 退出
- ✅ TypeScript strict 模式编译通过
- ✅ .env 加载（dotenv）

### 未通过 / 待修复

- ⚠️ Agent 循环无 multi-step（M2 修复）

- ⚠️ prompt 组装未走 waterfall（M2 修复）
- ❌ 无工具执行能力（M2 实现）

### 总评

M1 骨架**基本通过**验收。核心链路（用户输入 → LLM 流式响应 → 事件日志记录）完整打通，所有 11 个源文件均已实现。4 项偏差均为 M1 阶段的合理简化，不影响功能正确性，且均在 M2 计划中修复。
