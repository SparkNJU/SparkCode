## 实现方案对照

| 方案规划 | 实际实现 | 一致性 |
|----------|----------|--------|
| guard.ts — resolvePath / isWithinWorkspace / assertWritable / assertReadable | 完全一致，4 个函数均实现 | ✅ 一致 |
| fs.ts — read 带行号 + offset/limit | 完全一致，额外增加 50K 字符截断保护 | ✅ 一致+增强 |
| fs.ts — write 自动 mkdir | 完全一致 | ✅ 一致 |
| fs.ts — edit 唯一性校验 + diff 预览 | 完全一致，上下文 3 行 + `-`/`+` 标记 | ✅ 一致 |
| search.ts — glob 自己实现递归遍历 | 纯 Node.js 实现，无外部依赖，`globToRegex` + `walkDir` | ✅ 一致 |
| search.ts — grep 正则搜索 | 完全一致，带 glob 文件名过滤 + 大文件跳过（1MB） | ✅ 一致 |
| 结果截断 — glob 20K / grep 30K | glob 1000 条上限 / grep 500 条上限 + 单行 300 字符截断 | ⚠️ 简化 |

**结果截断实现偏差说明**：方案中写的是按字符数截断（glob 20K / grep 30K），实际实现为按条目数截断（glob 1000 条 / grep 500 条）。按条目数截断更合理——避免单条超长结果吞掉大量条目配额。属于可接受的实现优化。

## 与技术方案的偏差

| 偏差点 | 方案规划 | 实际实现 | 影响 |
|--------|----------|----------|------|
| 结果截断方式 | 按字符数（glob 20K / grep 30K） | 按条目数（glob 1000 / grep 500） | 无负面影响，更合理 |
| 外部依赖 | 方案提到可能用 glob 库 | 纯 Node.js 实现，零依赖 | 正面偏差，减少依赖 |
| ToolDefinition 泛型 | 方案设计用 `ToolDefinition<T>` | 实际接口非泛型，用 `as` 断言 | 无影响，适配现有接口 |
