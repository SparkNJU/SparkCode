## 1. 引言

### 1.1 目的

本文档定义 Spark Code 编程智能体的软件需求规格，作为设计、实现与验收的依据。文档覆盖系统功能需求、非功能需求、技术约束与外部接口。

### 1.2 范围

Spark Code 是一个**从零实现、不依赖任何 agent 框架/SDK** 的编程智能体。它通过与大语言模型多轮交互，自主读写文件、执行 Shell 命令，完成用户交付的编程任务。系统提供两种用户界面：CLI TUI（命令行终端）和 Web 界面（浏览器），两者共用同一套核心运行时。

本需求文档覆盖以下功能范围：

| 功能类别 | 包含内容 |
|---|---|
| 核心运行时 | 事件日志、事件总线、服务仓库、Agent 循环 |
| 工具系统 | bash、read、write、edit、glob、grep、web_fetch、todo_write、后台任务（job_*） |
| LLM 集成 | OpenAI 兼容 API、多模型支持、流式输出、tool calling |
| 上下文管理 | token 计量、工具结果裁剪、摘要压缩（两级） |
| 持久化 | JSONL 事件日志落盘、会话恢复（resume） |
| 界面 | CLI TUI + Web 界面（Vue3 + SSE） |
| 安全 | 工作区限制、高危命令审批 |

不在范围内：Docker 容器沙箱、web_search（需外部搜索 API）、平台级沙箱（landlock/seccomp）。

## 2. 总体描述

### 2.1 产品视角

Spark Code 是一个独立的编程智能体系统，不依附于任何现有 agent 产品或框架。系统的核心价值：

1. **自主编程能力**：Agent 能理解用户意图，自主规划执行步骤，通过读写文件和执行命令完成编程任务。
2. **从零实现**：对话管理、工具注册与执行、模型输出解析、循环终止、错误处理等核心逻辑全部自研。
3. **双界面**：CLI 和 Web 共用核心运行时，行为一致，展示架构设计能力。

### 2.2 用户角色

| 角色 | 描述 | 交互方式 |
|---|---|---|
| 开发者用户 | 通过 CLI 或 Web 界面向 Agent 提交编程任务 | CLI 命令行 / Web 浏览器 |
| 评委会 | 阅读 README、观看演示视频、现场提问答辩 | 文档 / 视频 / 面试 |

### 2.3 系统上下文

                        └──────────┬──────────────────────┘

                        └─────────────────────┘

### 2.4 约束与假设

**硬约束**（来自考核要求）：

- 不使用任何 agent 框架/SDK（LangChain、LlamaIndex、OpenAI Agents SDK 等）
- 不使用 API 服务端托管的代码执行或文件工具（Code Interpreter、Files API）
- 重要逻辑自行编写（对话历史管理、工具定义与执行、模型输出解析、循环终止、错误处理）
- API Key 仅通过环境变量提供，不得入库
- 允许使用模型厂商 API 客户端库（`openai` npm 包）和 OpenAI 兼容网关
- 允许使用通用非 agent 库（express、vue3、vite、markdown-it 等）

**假设**：

- 用户机器安装有 Node.js ≥ 20
- 用户可通过环境变量配置 API Key
- 目标 LLM 服务支持 OpenAI 兼容 API 和原生 tool calling

## 3. 功能需求

### 3.1 核心运行时

#### FR-3.1.1 事件日志（Session）

**描述**：系统以 append-only 的事件日志作为会话的唯一事实源（source of truth）。

**事件类型**：

| 事件类型 | 数据 | 分类 |
|---|---|---|
| `turn/start` | `{ turn: number }` | 日志型 |
| `turn/end` | `{ turn: number, reason: TurnEndReason }` | 日志型 |
| `step/start` | `{ turn: number, step: number }` | 日志型 |
| `step/end` | `{ turn: number, step: number }` | 日志型 |
| `user/message` | `UserMessage` | Surface（模型可见） |
| `assistant/chunk` | `{ turn, step, chunk: StreamChunk }` | 日志型 |
| `assistant/message` | `{ turn, step, message, usage? }` | Surface |
| `tool/call` | `{ turn, step, callId, name, arguments }` | 日志型 |
| `tool/result` | `{ turn, step, message, error? }` | Surface |
| `request/header` | `{ header, reason }` | 日志型 |
| `agent/inbox/spliced` | `InboxSplice` | 日志型 |
| `todo/write` | `{ todos: TodoItem[] }` | 日志型 |

**验收标准**：
- 每个事件带单调递增序号 `seq` 和时间戳 `time`
- Surface 事件（user/message、assistant/message、tool/result）可通过 `deriveMessages()` 投影为 LLM 历史消息
- 日志型事件不进入模型历史，但支持审计和重放
- 事件数据可 lossless-JSON 序列化

#### FR-3.1.2 事件总线（Event Bus）

**描述**：提供类型化的事件分发机制，支持 `emit`（广播）和 `waterfall`（中间件链）两种模式。

**验收标准**：
- `emit` 支持多监听器广播
- `waterfall` 支持链式数据变换（用于 prompt 组装、压缩策略等横切逻辑）
- 事件总线支持服务注册与查找（服务仓库模式）

#### FR-3.1.3 消息投影（deriveMessages）

**描述**：从事件日志投影出模型可见的历史消息序列。

**验收标准**：
- 只投影 Surface 事件（user/message、assistant/message、tool/result）
- assistant/message 内容为空时跳过（仅含 usage 的事件）
- 增量投影：维护游标，新事件增量追加，compaction 时重建

### 3.2 Agent 循环

#### FR-3.2.1 Turn/Step 状态机

**描述**：Agent 以 Turn（回合）和 Step（步）为单位驱动任务执行。

**状态流转**：
```
Idle → Running（wakeDriver）→ Idle（turn 结束且无 pending）
Idle → Maintenance（runMaintenance，压缩）→ Idle
Running → Running（下一个 step / 下一个 turn）
Running → Idle（cancel / 出错）
```

**验收标准**：
- `followup(content)` 产生 next-turn 输入，启动新回合
- `steer(content)` 产生 next-step 输入，追加到当前回合
- `inject(content)` 注入系统上下文（source: injected），不显示为用户消息
- `cancel(reason)` 中止当前回合，AbortSignal 贯穿所有工具

#### FR-3.2.2 循环终止条件

**描述**：Agent 循环必须有明确的终止条件，防止死循环。

| 条件 | 判定 | 动作 |
|---|---|---|
| 模型无 tool-call | `toolCalls.length === 0` | 回合完成 |
| step 数超上限 | `step >= maxStepsPerTurn` | 强制结束 |
| 无待处理输入 | 认领为空 | 回合完成 |
| `concludeTurn` 标记 | 工具显式标记 | 工具要求结束回合 |
| 模型 `finish_reason = length` | max-tokens 触顶 | sticky 记录，可继续 |
| 用户取消 | `cancel()` | 中止，已启动工具排空 |
| 致命错误 | LlmError / 未知异常 | error 结束 |

**验收标准**：
- `maxStepsPerTurn` 默认 50，可通过配置修改
- 每个终止条件均有对应的 turn/end 事件记录

#### FR-3.2.3 Inbox 消息队列

**描述**：管理待处理的用户/系统输入消息，支持 next-turn 和 next-step 两种优先级。

**验收标准**：
- `claim(target, turn)` 按优先级认领消息
- `hasPending()` 检查是否有待处理输入
- 支持在 Agent 运行时追加输入（不阻塞）

### 3.3 工具系统

#### FR-3.3.1 工具注册表（ToolRegistry）

**描述**：所有工具通过统一注册表注册，schema 自动汇入 system prompt，执行走统一管道。

**执行管道**：
1. **pre-execute 钩子**：权限校验、沙箱检查、审批
2. **执行本体**：包裹超时（60s 默认）与取消（AbortSignal）
3. **规范化**：任何 throw 转为 `isError` 结果

**验收标准**：
- 工具名唯一，重复注册抛错
- `schemas()` 返回所有已注册工具的 JSON Schema
- `execute()` 统一处理未知工具、权限拒绝、超时、异常

#### FR-3.3.2 工具结果格式

**描述**：所有工具返回统一的 `ToolResult` 结构。

```typescript
interface ToolResult {
  content: string              // 模型可见文本
  isError: boolean
  meta?: Record<string, unknown>  // UI 呈现用，不发给模型
}
```

**验收标准**：
- 工具异常不抛给模型，转为 `{ content: "Error: ...", isError: true }` 返回
- 模型能读到错误原因并自主修正（自我纠正机制）

#### FR-3.3.3 `bash` — Shell 执行

**描述**：在用户工作目录执行 Shell 命令，返回 stdout、stderr 与退出码。

**参数**：
- `command`（string，必填）：要执行的命令
- `run_in_background`（boolean，可选，默认 false）：后台运行
- `timeout_ms`（integer，可选，默认 60000）：超时毫秒

**验收标准**：
- 使用 `child_process.spawn` 执行，兼容 Git Bash 环境（Windows）
- 前台执行：超时中断、AbortSignal 取消（kill 进程树）
- 后台执行：返回 `job_id`，注册进 JobRegistry
- 输出截断：超过 20000 字符时保留头 80% + 尾 20%，中间落盘提示
- 退出码非 0 时 `isError: true`

#### FR-3.3.4 后台任务（job_* 工具族）

**描述**：支持长时间运行的命令在后台执行，并配套管理工具。

**工具清单**：
- bash（`run_in_background=true`）→ 返回 job_id
- `job_output`：读取后台任务增量输出
- `job_kill`：终止后台任务
- `job_list`：列出所有后台任务

**验收标准**：
- 后台任务不阻塞 Agent 循环
- 任务完成/失败时更新状态
- 可通过 job_id 查询、读取输出、终止

#### FR-3.3.5 `read` — 文件读取

**描述**：读取文件内容，返回带行号的文本。

**参数**：
- `path`（string，必填）：文件路径
- `offset`（integer，可选）：起始行（从 0 计）
- `limit`（integer，可选）：读取行数

**验收标准**：
- 支持相对路径（基于当前工作目录解析）
- 返回带行号格式：`L1\t内容\nL2\t内容\n...`
- 路径不存在时返回 isError 结果

#### FR-3.3.6 `write` — 文件写入

**描述**：创建或覆盖文件。

**参数**：
- `path`（string，必填）：文件路径
- `content`（string，必填）：文件内容

**验收标准**：
- 自动创建不存在的父目录
- 写前检查路径是否在工作区内（workspaceOnly 限制）
- 覆盖已有文件时返回 diff 信息

#### FR-3.3.7 `edit` — 精确字符串替换

**描述**：对文件做精确字符串替换（Claude Code 风格的 str_replace_editor）。

**参数**：
- `path`（string，必填）：文件路径
- `old_string`（string，必填）：要替换的原文
- `new_string`（string，必填）：替换后的内容
- `replace_all`（boolean，可选，默认 false）：是否替换所有出现

**验收标准**：
- `old_string` 必须在文件中唯一（除非 replace_all=true）
- 替换后计算 unified diff 返回
- 写前守卫：检查路径是否在工作区内

#### FR-3.3.8 `glob` — 文件搜索

**描述**：按 glob 模式查找文件路径。

**参数**：
- `pattern`（string，必填）：glob 模式（如 `src/**/*.ts`）

**验收标准**：
- 返回匹配的文件路径列表
- 可依赖 `fast-glob` 等通用库

#### FR-3.3.9 `grep` — 内容搜索

**描述**：在文件中按正则搜索，返回匹配行与行号。

**参数**：
- `pattern`（string，必填）：正则表达式
- `path`（string，必填）：搜索目标路径（文件或目录）

**验收标准**：
- 返回格式：`文件路径:行号: 匹配内容`
- 支持递归目录搜索
- 正则语法错误时返回 isError 结果

#### FR-3.3.10 `web_fetch` — 网页抓取

**描述**：抓取指定 URL 的文本内容。

**参数**：
- `url`（string，必填）：目标 URL

**验收标准**：
- 使用 `fetch` API 获取 HTML
- 剥离 `<script>`、`<style>` 标签，提取纯文本
- 超过 20000 字符时截断
- 网络错误返回 isError 结果
- 支持 AbortSignal 取消

#### FR-3.3.11 `todo_write` — 待办管理

**描述**：管理任务待办列表，帮助 Agent 规划和追踪复杂任务。

**参数**：
- `todos`（array，必填）：待办项列表

**验收标准**：
- 全量快照写入（last-write-wins）
- 事件 `todo/write` 落日志（仅 UI 状态，不进模型历史）
- Web 界面展示 Todo 面板

#### FR-3.3.12 沙箱与审批

**描述**：限制工具执行的安全边界。

**L1 工作区限制**：
- 所有 fs 写操作（write、edit）检查路径是否在 `cwd`（工作区）内
- `workspaceOnly=true` 时越界写直接拒绝
- `approvalForOutside=true` 时发起审批

**L2 高危命令审批**：
- bash 命令匹配高危模式时触发审批
- 高危命令清单：`rm -rf`、`sudo`、`mkfs`、`dd`、`curl ... | sh`、全局包安装等
- 审批方式：CLI 终端提问 / Web 弹窗确认

**验收标准**：
- 工作区限制默认开启
- 高危命令审批默认开启
- 审批拒绝时返回 isError 结果给模型

### 3.4 LLM 集成

#### FR-3.4.1 LLM 适配器

**描述**：通过 OpenAI 兼容 API 接入大语言模型。

**验收标准**：
- 使用 `openai` 官方 npm 包作为客户端
- `baseURL` 可配置，指向任意 OpenAI 兼容服务（DeepSeek、GPT 等）
- 支持流式输出（`stream: true`）
- 支持原生 tool calling（`tools` 参数）

#### FR-3.4.2 多模型支持

**描述**：用户可通过命令行参数或配置文件切换模型。

**验收标准**：
- `--model <model>` 命令行参数指定模型
- 环境变量 `SPARK_MODEL` 设置默认模型
- 配置文件 `config.model` 字段设置默认模型
- 命令行参数 > 环境变量 > 配置文件 > 内置默认值

#### FR-3.4.3 流式输出解析（BlockAssembler）

**描述**：将 LLM 的 SSE 流式增量组装为完整消息，核心自研逻辑。

**关键技术点**：
1. SSE 增量按 `delta.content` / `delta.tool_calls` / `finish_reason` 分类
2. tool-call 的 `arguments` 是按 index 分片的 JSON 字符串，需聚合后整体 parse
3. `JSON.parse` 失败不崩溃，保留原文交给工具层做参数校验

**验收标准**：
- `BlockAssembler` 正确拼接 content 和 tool-call 块
- tool-call arguments 分片聚合后 JSON.parse，失败时返回 `{ _raw: 原文 }`
- `finish()` 返回 `{ content: ContentBlock[], finishReason }`

#### FR-3.4.4 历史消息转换（toApiMessages）

**描述**：将 session 投影的历史消息转换为 OpenAI API 格式。

**验收标准**：
- user/message → `{ role: 'user', content }`
- assistant/message → `{ role: 'assistant', content: text, tool_calls: [...] }`
- tool/result → `{ role: 'tool', tool_call_id, content }`

#### FR-3.4.5 重试策略

**描述**：LLM 请求失败时的重试机制。

| 错误类型 | HTTP 状态码 | 策略 |
|---|---|---|
| 限流 | 429 | 指数退避重试，最多 3 次 |
| 鉴权失败 | 401 | 不重试，报凭据错误 |
| 网络超时 | — | 重试 1 次 |
| 其他错误 | — | 不重试，返回 LlmError |

**验收标准**：
- 重试逻辑放在 `llm/stream` waterfall 中间件，与核心逻辑解耦
- 每次重试记录日志
- 重试耗尽后抛出 LlmError（带 code 和 status）

#### FR-3.4.6 结构化错误（LlmError）

**描述**：LLM 层的统一错误结构。

```typescript
interface LlmFailure { message: string; code: string; status?: number }
```

**错误码**：
- `AUTH`：鉴权失败
- `RATE_LIMIT`：限流
- `NO_ADAPTER`：未找到适配器
- `UNKNOWN`：未知错误

**验收标准**：
- LlmError 包含 failure 结构化对象
- 循环层捕获 LlmError 记录为 `turn/end reason: { kind: 'error' }`
- UI 层显示红色错误信息 + 错误码

### 3.5 上下文管理

#### FR-3.5.1 Token 计量

**描述**：估算当前上下文的 token 用量，触发压缩。

**估算策略**：
- 中文字符：1.6 字符/token
- 英文字符：4 字符/token

**验收标准**：
- `estimateTokens(text)` 返回估算 token 数
- 累计值与 LLM 返回的 `usage.total_tokens` 校准
- 超过 `maxContextTokens` 阈值时触发压缩

#### FR-3.5.2 工具结果裁剪（第一级压缩）

**描述**：超长工具结果在进入历史前就地截断。

**截断策略**：
- 阈值：`maxToolResultChars`（默认 20000 字符）
- 保留头 80% + 尾 20%
- 中间插入提示：`…[输出已截断，共 N 字符，完整输出见 文件路径]…`
- 截断的完整内容写入临时文件供后续 read

**验收标准**：
- 截断后的文本不超过阈值的 120%（头+尾+提示）
- 临时文件可被 read 工具读取
- 截断操作记录日志

#### FR-3.5.3 摘要压缩（第二级压缩）

**描述**：当上下文 token 超过阈值时，将早期对话摘要化。

**压缩策略**：
- 触发条件：`estimateTokens(deriveMessages) > maxContextTokens`
- 默认策略：把最早 N 轮对话用一个"摘要 user/message"（source: injected）替换
- 替换标记：`surfaceOp: { op: 'replace', start, end }`
- 核心不变式：替换只影响模型可见表面（surface），原始日志事件保留

**验收标准**：
- 压缩后模型看到的是语义摘要而非截断文本
- 原始日志事件不被修改（可审计、可展开）
- 压缩操作记录为 `compact/turn` 事件

### 3.6 持久化

#### FR-3.6.1 JSONL 日志落盘

**描述**：会话事件日志以 JSONL 格式持久化到磁盘。

**验收标准**：
- 每行一个 JSON 事件对象
- 文件路径：工作区下 `.spark/sessions/<sessionId>.jsonl`
- flush 策略：每个 turn 结束后 flush
- 进程异常退出时不丢失已 flush 的事件

#### FR-3.6.2 会话恢复（resume）

**描述**：重启后可通过 `spark --resume <sessionId>` 恢复会话。

**验收标准**：
- 重放 JSONL 日志重建事件序列
- 从日志投影历史消息，恢复 Agent 状态
- 恢复后可继续对话（新 turn 正常工作）
- 会话列表可通过 `GET /api/sessions` 查询

### 3.7 CLI 界面（TUI）

#### FR-3.7.1 命令行接口

```
Usage:
  spark [options] [task...]

Options:
  -m, --model <model>        指定模型
  -w, --workspace <dir>      工作目录（默认当前目录）
  -p, --print                打印最终结果后退出（one-shot 模式）
  -i, --interactive          交互式 REPL（默认）
  --no-color                 禁用颜色
  -h, --help                 帮助
  --resume <sessionId>       恢复已有会话
```

**验收标准**：
- 无参数时进入交互式 REPL
- 带 task 参数时进入 one-shot 模式（`-p` 打印结果后退出）
- `--resume` 恢复指定会话

#### FR-3.7.2 交互式 REPL

**描述**：基于 Node `readline/promises` 的零依赖交互终端。

**输入模式**：

| 前缀 | 模式 | 行为 | 示例 |
|---|---|---|---|
| `!` | 命令模式 | 直接执行 Shell 命令，不经过 LLM | `!ls -la` |
| 无 | 对话模式 | 发送给 LLM，由 LLM 决定是否调用工具 | `帮我写个函数` |

**欢迎消息**：REPL 启动时显示模型名称、工作目录，并提示 `!` 前缀的命令模式用法。

**验收标准**：
- 支持多行输入
- `!` 前缀直接执行 Shell 命令（绕过 LLM，不消耗 token）
- 无前缀输入走 LLM 对话（Agent 决定是否调用工具）
- Ctrl+C 一次取消当前回合，两次退出进程
- `followup` 语义：每次输入启动新 turn
- 欢迎消息明确提示两种输入模式

#### FR-3.7.3 TUI 渲染

**描述**：事件流的纯函数渲染。

| 事件 | 渲染方式 |
|---|---|
| 流式文本（assistant/chunk） | 逐 chunk 打印，不使用清屏 |
| 工具调用（tool/call） | `🔧 bash("npm test")` 形式 |
| 工具结果成功 | 绿色缩进块 |
| 工具结果失败 | 红色缩进块，截断显示 `…（已截断）` |
| 错误 | 红色 `✗` 前缀 + 结构化 code |
| 回合结束 | 等待下一次输入 |

**验收标准**：
- 颜色使用 ANSI 转义码
- `--no-color` 关闭所有颜色
- 所有渲染为事件的纯函数（与 Web 渲染逻辑一致）

### 3.8 Web 界面

#### FR-3.8.1 后端 API

**REST 端点**：

| 方法 | 路径 | 功能 | 请求/响应 |
|---|---|---|---|
| POST | `/api/session` | 创建会话 | → `{ sessionId }` |
| GET | `/api/session/:id` | 会话元数据 | → 元数据 + 最近事件 |
| POST | `/api/session/:id/message` | 发送消息 | `{ content }` → `{ ok }` |
| GET | `/api/session/:id/stream` | SSE 事件流 | `text/event-stream` |
| POST | `/api/session/:id/cancel` | 取消回合 | → `{ ok }` |
| GET | `/api/sessions` | 会话列表 | → `[{ id, ... }]` |
| DELETE | `/api/session/:id` | 删除会话 | → `{ ok }` |
| GET | `/api/tools` | 工具 schema | → `[ToolSchema]` |
| GET | `/api/config` | 脱敏配置 | → `SparkConfig`（不含 key） |

**SSE 事件格式**：

```
event: session/event
data: {"seq":12,"type":"assistant/chunk","data":{"text":"..."}}

event: agent/status
data: {"status":"running"}

event: turn/end
data: {"reason":{"kind":"completed"}}
```

**验收标准**：
- Express 后端与 CLI 共用同一套核心运行时
- SSE 连接在 turn 开始时建立，turn 结束后保持（支持多回合）
- 并发会话支持：每个 sessionId 独立的 Agent 实例

#### FR-3.8.2 前端页面布局

│ Header: Spark Code | 模型选择 | 会话列表 | 工作区  │
├──────────┬───────────────────────────────────────┤

│ 会话列表   │  ├ 用户消息                           │

#### FR-3.8.3 前端组件

| 组件 | 功能 |
|---|---|

## 4. 非功能需求

### 4.1 性能

| 指标 | 要求 |
|---|---|

| 工具执行超时 | 默认 60s，可配置 |

| SSE 事件延迟 | ≤ 100ms（本地网络） |
| 内存占用 | 单会话 ≤ 200MB（不含 LLM 响应） |

### 4.2 安全

| 需求 | 实现 |
|---|---|
| API Key 不入库 | 仅从环境变量 `SPARK_OPENAI_API_KEY` 读取 |

| 配置脱敏 | `/api/config` 返回不含 key 的配置 |
| 凭据泄漏防护 | 日志中不记录 API Key |

### 4.3 可靠性

| 需求 | 实现 |
|---|---|
| 工具异常不崩溃 | 统一转为 isError 结果返回模型 |
| LLM 错误可恢复 | 结构化 LlmError + 重试策略 |
| 会话可恢复 | JSONL 日志 + resume |
| 取消不泄漏 | AbortSignal 贯穿，已启动工具排空 |

### 4.4 可维护性

| 需求 | 实现 |
|---|---|
| TypeScript 严格模式 | `tsconfig.json` 中 `strict: true` |
| 核心逻辑与界面解耦 | CLI/Web 共用核心运行时 |
| 工具可扩展 | 注册表模式，新增工具只需实现 ToolDefinition 接口 |
| 事件驱动 | 横切逻辑通过 waterfall 中间件注入 |

### 4.5 可测试性

|---|---|
| session 事件日志 | 事件追加、投影、重放 |
| BlockAssembler | tool-call 分片聚合、JSON 容错 |
| deriveMessages | Surface 事件投影正确性 |
| 循环终止条件 | 各终止条件的边界测试 |
| 工具执行 | 各工具的基本功能与错误处理 |
