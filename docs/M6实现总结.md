## 1. 实现功能清单

### 1.1 命令系统重构 ✅

**目标**：从硬编码 if/else 改为 CommandRegistry 注册机制

**实现**：
- `src/commands/registry.ts` — 命令注册表
- `src/commands/builtin.ts` — 内置命令迁移
- `src/commands/index.ts` — 模块入口

**特性**：
- 统一的命令注册接口
- 别名支持（如 `/help` → `/?`）
- Tab 补全支持
- 帮助文本自动生成

### 1.2 模型切换 ✅

**目标**：运行时切换 LLM 模型

**实现**：
- `src/commands/model.ts` — `/model` 命令
- `src/core/loop.ts` — `setModel()` 方法
- `src/core/llm.ts` — `updateConfig()` 方法

**特性**：
- `/model` 显示可用模型列表
- `/model <name>` 按名称切换
- `/model <number>` 按序号切换
- 支持环境变量 `SPARK_MODELS` 自定义模型
- 切换后保留对话上下文

**使用示例**：
```
/model                    # 显示模型列表
/model mimo-v2.5-pro      # 切换到 mimo-v2.5-pro
/model 2                  # 切换到第 2 个模型
```

### 1.3 Skill 系统 ✅

**目标**：自定义斜杠命令

**实现**：
- `src/skills/loader.ts` — Skill 加载器
- `src/commands/skills.ts` — Skill 命令注册

**特性**：
- 两层目录：项目级 (`.spark/commands/`) + 用户级 (`~/.spark/commands/`)
- Markdown 文件格式
- YAML frontmatter 定义元数据
- `$ARGUMENTS` 占位符替换
- Tab 补全支持

**Skill 文件格式**：
```markdown
---
description: 修复 GitHub issue
---
修复以下 issue：
$ARGUMENTS

搜索相关文件，理解上下文，应用修复，然后运行测试。
```

**内置示例**：
- `.spark/commands/fix-issue.md` — 修复 GitHub issue
- `.spark/commands/review.md` — 代码审查

### 1.4 模式切换 ✅

**目标**：Normal/Plan/Auto 三种执行模式

**实现**：
- `src/core/modes.ts` — 模式定义
- `src/commands/mode.ts` — 模式切换命令
- `src/tools/registry.ts` — 工具过滤支持

**模式说明**：

| 模式 | 命令 | 工具权限 | 用途 |
|------|------|---------|------|
| Normal | `/normal` | 所有工具 | 默认模式 |
| Plan | `/plan` | 只读工具 | 分析规划 |
| Auto | `/auto` | 所有工具自动批准 | 快速执行 |

**使用示例**：
```
/plan                      # 切换到规划模式
/plan 分析这个项目的架构     # 切换并立即执行任务
/auto                      # 切换到自动模式
/normal                    # 切换回普通模式
```

### 1.5 Effort 级别 ✅

**目标**：控制推理深度

**实现**：
- `src/core/effort.ts` — Effort 定义
- `src/commands/effort.ts` — `/effort` 命令

**级别说明**：

| 级别 | 效果 |
|------|------|
| low | 快速简短回答 |
| medium | 平衡速度与质量（默认） |
| high | 深度分析，详细推理 |

**使用示例**：
```
/effort                   # 显示当前级别和说明
/effort low               # 设置为快速模式
/effort high              # 设置为深度分析模式
```

### 1.6 Tab 补全 ✅

**目标**：输入 `/` 后 Tab 补全命令

**实现**：
- `src/ui/completer.ts` — 补全函数
- 集成到 readline

**特性**：
- 输入 `/` 后按 Tab 循环补全
- 支持前缀匹配
- 包含所有内置命令和自定义 Skill

### 1.7 动态提示符 ✅

**目标**：显示当前状态

**实现**：
- `src/ui/prompt.ts` — 提示符构建

**格式**：
```
⚡ spark [模型] [模式] [effort] >
```

**示例**：
```
⚡ spark [mimo-v2.5] >                    # 默认状态
⚡ spark [mimo-v2.5] [plan] >             # 规划模式
⚡ spark [mimo-v2.5] [high] >             # 高推理深度
⚡ spark [mimo-v2.5-pro] [auto] [low] >   # 自动模式 + 低推理深度
```

## 6. 设计决策

### 6.1 命令系统

**决策**：CommandRegistry 注册机制
**理由**：
- 扩展性好：新增命令只需 `registry.register()`
- 支持 Tab 补全：所有命令名集中管理
- 支持别名：一个命令可有多个别名
- 帮助文本自动生成

### 6.2 模型切换

**决策**：复用 OpenAI 兼容客户端，仅切换 model/baseURL
**理由**：
- SparkCode 统一使用 OpenAI 兼容协议
- 不需要多 Provider 工厂模式
- 简化实现，减少代码复杂度

### 6.3 Skill 系统

**决策**：两层目录（user/project），直接作为命令执行
**理由**：
- 个人项目不需要内置 Skill
- 简化实现，减少维护成本
- 项目级覆盖用户级，满足不同项目需求

### 6.4 模式切换

**决策**：单一 Agent + 模式配置 + 工具过滤
**理由**：
- 不需要多个 Agent 类
- 通过工具过滤实现模式限制
- 模式切换简单，只需设置过滤器
